# Browser companions

One shared implementation lives in `extension/shared`. The build generates only the manifest/background-loader differences required by Chrome, Edge and Firefox. Extension version 0.1.3 is development software, independently versioned in `extension/version.json` from the desktop tool. Actual Chrome and Edge controlled journeys pass with extension 0.1.3 with the signed 0.1.1 desktop tool in standalone and suite forms on macOS 27.0.1 arm64. Firefox 159.0.1 also passes the controlled signed standalone and suite journey with extension 0.1.3. Signed extension distribution and public store availability remain pending.

## Build and development installation

Use the pinned Node runtime and repository lockfile. Run `npm ci`, then `npm run build:extensions` on the development host under its storage guard. Python 3 with zipfile/zlib is required for deterministic ZIP creation. Files are sorted, timestamps and modes fixed. Record Node, Python and zlib versions when comparing builds. Output is `extensions-dist/matiq-guides-<browser>-0.1.3.zip` and an unpacked directory per browser. These are unsigned developer packages, not store-approved releases.

For Chrome, open `chrome://extensions`, enable Developer mode, choose Load unpacked and select `extensions-dist/chrome`. For Edge use `edge://extensions` and `extensions-dist/edge`. For Firefox, use `about:debugging#/runtime/this-firefox`, Load Temporary Add-on, then select `extensions-dist/firefox/manifest.json`. Temporary Firefox add-ons do not survive browser restart; release distribution requires a genuinely Mozilla-signed package. Do not disable signing protections in a production browser profile.

The Chromium public development key pins the unpacked extension identity. Firefox uses `guides@matiqinc.com`. Store-assigned identities must be reviewed and allowlisted before store release; do not assume an Edge/Chrome store identity matches an unpacked build. Opening the extension never installs a desktop tool or marketplace package.

## Native bridge setup on macOS

Build the native helper with `npm run build:native` on the authorized Mac. The release build must sign/notarize the application and its native resources through the qualified SDK signing helpers. The helper targets arm64 macOS 14.2 for linking; this minimum is not a workflow qualification claim for untested macOS versions. The helper is a standalone native executable; end users do not install Node or Python.

In Guides, open/create a guide, enable its browser bridge, choose Chrome, Edge or Firefox, and explicitly install the approved native bridge. Registration is user-local and restricts allowed extension identities. The installer copies immutable versioned native bytes into a shared integration directory, records standalone/suite consumers and preserves compatible existing registrations. Both forms use the same integration. Updates cannot replace unknown registrations or different bytes under an existing bridge version. Application uninstall must not remove this shared directory or another form's registration. User projects are preserved separately.

Then open the extension from the intended browser tab, connect, explicitly select the receiving application, and start capture into the open guide. The desktop asks for confirmation of the guide and origin. Only one compatible standalone/suite adapter can own Guides at a time, enforced by SDK 0.1.3; close it in the other form before opening here. A second browser cannot compete for an owned capture. Disconnect explicitly before handing ownership to another browser.

## Scope and permissions

Core permissions: activeTab, scripting, storage and nativeMessaging. No site access is granted at installation. Toolbar invocation grants temporary access to the selected HTTP(S) tab. Firefox revokes temporary access on full navigation. Before starting or resuming, Firefox users may select “Continue across page navigation” and approve its real optional all-sites permission prompt: Firefox requires this broader permission for continuous screenshots ([Mozilla screenshot API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/captureVisibleTab)). The option is off by default. Denial does not start recording. A granted browser permission remains until removed in Firefox extension settings; pause/stop still deactivate recording hooks immediately. Guides continues to enforce the selected active tab and HTTP(S) scope, including after navigation, before injection or screenshots. If navigation revokes access, capture pauses visibly; open the extension on the new page and explicitly resume. Changing the active tab pauses capture; choose the intended tab and resume explicitly. Browser-internal pages, extension pages, local files and embedded frames are unsupported. Frame presence produces a saved warning. Closed shadow controls and other unsupported interactions still need further qualification.

Chrome/Edge have a service worker; Firefox loads the same implementation as background scripts. The native host uses framed JSON on stdio and a private authenticated Unix socket to the receiving desktop adapter. There is no localhost HTTP control API. Both ends bound message sizes and validate protocol/session/sequence ownership. Page content cannot execute native commands or read files.

## Privacy, buffering and failures

The extension captures screenshots and structured actions only while active in the selected scope. It has no raw keyboard, password or clipboard listener. Form instructions never contain field values. Sources retain HTTP(S) origins only, without paths, credentials, query strings or fragments. Control labels are bounded and filtered; screenshot pixels can still contain sensitive information. Always review and redact before sharing.

Screenshots are captured as high-quality JPEG. Oversized frames are resized to fit the bounded native protocol. Screenshot context is sampled after browser capture throttling, so changes while waiting do not invalidate an otherwise stable screenshot. Scrolling and normal browser zoom use viewport geometry; pinch zoom, dynamic transitions, rapid repeated actions and browser-specific limits need additional native acceptance tests. Unreliable screenshots/targets pause capture or produce an explicit review warning rather than a false completion claim. Double-click instructions currently require manual review.

Acknowledgements follow durable desktop persistence. A pending queue is limited to four steps or 3 MiB, plus one current in-memory baseline screenshot while recording. The queue survives service-worker restart in local extension storage and is removed as steps are acknowledged. Disconnect immediately stops capture hooks. Reconnect and select the same receiving session to reconcile acknowledged sequences; explicitly resume before more capture. Queue overflow pauses recording visibly. Discarding pending steps is explicit and leaves a warning in the desktop guide. Cancelling while disconnected remains pending until the desktop receives cancellation.

Firefox declares browsingActivity, websiteActivity and websiteContent because Mozilla counts transfer to a local native application as data transmission. There is no upload, analytics, telemetry, remote favicon request, cloud processing, model or account requirement.

## Current evidence and limits

`npm run test:browser` uses an actual Chromium extension, actual toolbar UI, trusted browser input, screenshots, native messaging and the real SDK standalone workspace on Linux. Its native transport launcher and desktop approval choices are controlled fixtures. It exercises browser navigation, scrolling, safe form descriptions, pause/resume, actual native-host exit after a deliberately dropped durable acknowledgement, deduplicated reconnect, desktop stop and a second cancelled session. It also disposes a running adapter, awaits browser-hook acknowledgement and verifies its recoverable paused checkpoint. It independently verifies owned process/listener cleanup. This does not qualify Chrome, Edge, Firefox or a packaged macOS application.

`npm run test:native` exercises the actual compiled macOS stdio helper and validates framed authentication, Unicode transport, malformed-size rejection and cleanup. It refuses to adopt an existing active bridge. Native helper tests alone do not qualify browser installation, store signing or packaged workflows.

The macOS browser fixture uses trusted character typeahead for its native HTML select, verifies that the controlled selection changed, then requires the captured step. macOS native select popup arrow-key delivery is a documented CDP limitation ([ChromeDevTools issue 3033](https://github.com/ChromeDevTools/chrome-devtools-mcp/issues/3033)); programmatic untrusted change events are not substituted for captured user input. Native popup mouse selection remains a separate qualification case.

## Actual packaged Chrome and Edge evidence

Installed Chrome 157.0.8103.38 and Edge 157.0.4341.42 use the actual company-signed native host from desktop candidate 0.1.1 (source 33776f4), extension 0.1.3 and protocol 1. The controlled journey selects the receiving form, records navigation/scrolling/trusted field changes/native select typeahead, verifies target geometry, pauses/resumes, terminates the real owned native host, reconnects without duplicates, stops from the desktop, cancels a subsequent capture without removing earlier steps and quits normally. Owned processes, connection records and loopback fixture listeners are independently absent afterward. Application approval choices and fixture content are controlled; transport and capture are real. These are unpacked development-extension tests, not store distribution or complete browser acceptance. SPA/zoom/tab-change/restart/native popup mouse interaction and other cases still need qualification.

Use the actual installed executable in `GUIDES_EXECUTABLE_PATH`, its exact `mac-signature.json` in `GUIDES_CANDIDATE_PROOF`, and `GUIDES_TEST_BROWSER=chrome` or `edge`, then run `npm run test:browser` under the native storage guard. For suite execution, supply `GUIDES_SUITE_EXECUTABLE_PATH` and the real signed package in `GUIDES_SUITE_PACKAGE` instead of the standalone executable. The test verifies the signed app/source, installs the real suite package through SDK ToolStore when applicable, and uses isolated canonical profiles. It explicitly installs the native bridge through Guides. A copy of that app-generated registration is placed under the custom browser user-data directory, as required by browser native-host lookup. Experimental browser test debugging flags load the real unpacked extension and invoke its actual toolbar action. No test debugging permissions or controlled transport shim are shipped.

Run `npm run test:firefox` on the authorized Mac under its storage guard, with the same packaged-app proof and standalone/suite environment variables described above, plus `GUIDES_GECKODRIVER` pointing to verified test-only Mozilla geckodriver 0.37.1. Do not run this harness against a personal browser session. This is not signed Firefox distribution, restart persistence, store availability or complete browser acceptance.

## Pending-action interruption correction

Extension 0.1.4 records a canonical incomplete-capture warning when Pause or Stop interrupts an already observed action before it enters the persisted delivery buffer. Capture hooks and screenshot waits still stop immediately. Optional baseline refreshes are excluded; cancellation intentionally discards the session. The 0.1.3 defect was reproduced with actual Chromium input and the SDK workspace: a click waiting for the browser screenshot rate limit vanished without a step or warning. `GUIDES_TEST_FAST_STOP=1 npm run test:browser` adds the regression, including rapid desktop Pause and Stop. Linux uses the documented controlled transport; actual packaged macOS regression remains a separate evidence gate. No protocol, project data version or desktop SDK change is needed.

The previous 0.1.3 developer extensions also pass the six controlled browser journeys against signed desktop 0.1.2/source d582c20. Both forms pass a Chrome/TextEdit mixed guide and actual captured-project cross-form round-trip; see DESKTOP-CAPTURE.md. This evidence does not qualify the new extension until its own real-browser package checks pass.
