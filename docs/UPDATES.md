# Standalone updates

The standalone macOS arm64 entry point enables explicit update controls. The suite package keeps these controls hidden and uses its existing suite updater. One tool implementation and qualified SDK/runtime/shell 0.1.3 remain shared. Core workflows never check for updates automatically. Checking contacts the existing GitHub release provider; it sends no guide, URL, screenshot or interaction content. No account or model is required for core use. Until releases are published, the release check can fail visibly.

The updater is pinned to the installed suite’s MIT-licensed electron-updater 6.8.9. Its download cache is under host.dataDir/updates. The narrow integration suppresses its persisted rollout identifier and removes the rollout header before every request. It uses a temporary authenticated loopback feed owned by that updater to hand the verified download to macOS Squirrel. This feed serves an update only, never commands or guide data. Squirrel also uses its OS-managed application staging area outside the guide project.

Check for updates shows the compatible version and ZIP size. Download is an explicit choice. The release metadata must identify com.matiq.guides, SDK 0.1.3, electron-45.2.3 and dataVersion 1, with the exact arm64 ZIP name, bounded size and SHA-512. Mismatch blocks download visibly. Downloaded bytes receive updater integrity checks and native signature/staging verification. Errors retain the saved guide and permit retry. Connections have inactivity timeouts. Download, check and native verification make the SDK report busy. If a connection cannot be stopped, Retry update cleanup remains available and closing stays blocked. Native verification must report a terminal result before cleanup can be declared successful.

After staging, the update applies at the next safe launch. Restart now requests an ordinary SDK quit; status checks and dispose finish before the will-quit installation trigger. It never calls the native installer while a live guide workspace still needs the SDK’s shutdown checks. The owned proxy is closed before the staged state is ready. Unsaved work, active capture and failed persistent cleanup block restart through the ordinary tool status contract. Hiding preserves work. The code does not replace or patch shared shell/runtime behavior.

The integration audits two private details of pinned updater 6.8.9: its staging-ID generator and local Squirrel server reference. The version assertion fails visibly on substitution. The server is explicitly closed and awaited; owned native listeners and request timeouts are removed during disposal. Do not upgrade this dependency without requalifying those contracts and an actual signed N to N+1 native update.

Primary references: [Electron native updater](https://www.electronjs.org/docs/latest/api/auto-updater/), [Squirrel.Mac](https://github.com/Squirrel/Squirrel.Mac), and the installed suite’s exact 6.8.9 implementation/type declarations. Current v27 updater documentation describes v7 breaking changes and is not the implementation contract for this pin. No competitor source was consulted for updating.

## Acceptance status

Source integration and metadata checks are development evidence. Actual production-signed N and N+1 packages, real download/native staging, refusal of unsaved restart, process replacement/relaunch, preserved guide bytes/assets and independent owned-resource absence must pass before this workflow is qualified. A controlled test-owned loopback release feed may exercise the same real updater with real signed artifacts; that is candidate execution, not a published release endpoint.
